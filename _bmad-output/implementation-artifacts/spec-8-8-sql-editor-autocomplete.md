## Intent

**Problem:** The ad-hoc SQL surface (`QueryTabView`) is a plain `<textarea>` — no syntax highlighting, no autocomplete. A developer typing a query gets no keyword coloring and no help recalling the schema/table/column names the app *already* introspected on connect; they must switch to the schema tree and copy names by hand. Every real SQL editor colors keywords and completes identifiers from the live schema. `design-artifacts/workspace.html` (the visual source of truth) already shows the editor as a type-colored SQL pane, but the shipped editor renders none of it — the prototype's colored spans are a static mock over a bare textarea.

**Approach:** Replace the `<textarea>` in `QueryTabView` with a **CodeMirror 6** editor (decision already made — this spec does NOT weigh alternatives). Configure three things: (1) the SQL language + keyword syntax highlighting via `@codemirror/lang-sql`, themed through a custom `HighlightStyle` mapped to net-new `--sql-*` tokens ported from `workspace.html`; (2) a **schema-driven completion** built from the ALREADY-loaded schema (the `tables: ReadonlyArray<SchemaTableInfo>` the app already threads down for the ERD — no new RPC), surfacing schema / table / column names on `Ctrl+Space` AND as-you-type after a prefix; (3) a **neutral CodeMirror theme** built from the project's existing `globals.css` tokens (`--background`, `--foreground`, `--font-mono`, `--coral-soft` selection, `--card`/`--border` autocomplete popup) so the editor matches the neutral shell. The `⌘/Ctrl+Enter → Run` binding, the guarded `execute` RAW round-trip (`run-raw-query.ts`), the enable gate, the `firing` re-entrancy guard, the session-draft persistence contract, and the Core-is-the-sole-gate model are all preserved. The completion-config builder is extracted as a pure, DOM-free module so it stays unit-testable in a repo with no jsdom.

## Boundaries & Constraints

**Always:**
- Replace the `<textarea>` in `QueryTabView` with a CodeMirror 6 `EditorView`, mounted into a React `useRef` container inside a `useEffect` (create on mount, `view.destroy()` on unmount). Everything else in the component tree (the editor bar, the ink-filled Run control, the pager, the result banners, the `DataGrid`) stays React-rendered and unchanged.
- Preserve the lifted session-draft contract EXACTLY: CodeMirror's `updateListener` fires `onDraftChange(view.state.doc.toString())` on every doc change, so `App`'s `queryDrafts` map still holds the per-Tab draft and the Story 3.6 "draft survives Tab switch, gone on relaunch" AC still holds (query text still never touches disk / the snapshot). Initialize the CM doc from the `draft` prop on mount.
- Keep `⌘/Ctrl+Enter → Run`: bind a CodeMirror keymap `{ key: "Mod-Enter", run: … }` (CM's `Mod` = Cmd on mac, Ctrl elsewhere — matches the existing `metaKey || ctrlKey` semantics) that invokes the current `run()` via a ref (`runRef.current`) to avoid a stale-closure over `draft`/`busy`/`confirm`. Run must still read the editor's current text (the CM doc) and send it verbatim.
- Send the editor text **verbatim** through `runRawQuery(sql)` / `runRawQuery(sql, true)` — the UI never parses, splits, classifies, tokenizes for execution, or composes SQL (AR-3). Syntax highlighting + autocomplete are presentation/authoring aids ONLY; the bytes sent to `execute` are the doc text unchanged. `run-raw-query.ts`, `RunOutcome`, the `confirmed:true` re-issue, and the Core gate stay byte-for-byte unchanged.
- Feed the completion source from the schema ALREADY loaded client-side — the `tables` prop already threaded `App.allTables → Workspace(allTables) → TabContent(tables)` — introducing NO new RPC. `TabContent`'s `query` branch passes `tables={tables}` into `QueryTabView`; `QueryTabView` adds an optional `tables?: ReadonlyArray<SchemaTableInfo>` prop. Completion options are derived from `table.schema`, `table.name`, and `table.columns[].name`.
- Build the completion config from `tables` via a PURE exported helper in its own DOM-free module (e.g. `sql-completions.ts`), unit-tested with `bun:test` — mirroring how `run-raw-query.ts` was extracted so the round-trip is testable without a live DOM. The completion source must (a) offer matching schema/table/column names on explicit `Ctrl+Space`, and (b) offer them as-you-type once a prefix has been typed.
- Theme CodeMirror neutral, off `globals.css` tokens: `EditorView.theme(...)` for chrome (background `var(--background)`, text `var(--foreground)`, `var(--font-mono)` ~13px/1.7, selection `var(--coral-soft)`, caret `var(--foreground)`, gutters neutral, autocomplete popup on `var(--card)`/`var(--border)`/`var(--radius)` with the active option on `var(--coral-soft)`/`text-coral`) and a `HighlightStyle.define(...)` (via `@codemirror/language` + `@lezer/highlight` `tags`) mapping keyword/string/number/function/punctuation to the net-new `--sql-*` tokens. Keep CM's focus discreet (no harsh default outline) — rely on the container's existing ink `:focus-visible` ring idiom.
- Preserve the editor's accessible + testable input contract: the CM editable surface keeps an accessible name equivalent to today's `aria-label="sql query editor"` (via `EditorView.contentAttributes` / editor DOM), and the editor mount container carries a stable `data-testid` (e.g. `sql-editor`) so the updated tests and the live check can target it without depending on a `<textarea>`.
- Add the net-new `--sql-*` tokens to `globals.css` dark-first `:root` (ported from `workspace.html` lines 46–51): `--sql-kw: #f0868a; --sql-fn: #c9a2f0; --sql-str: #8dd6a0; --sql-num: #82aaff; --sql-idn: #ececec; --sql-pun: #8f8f8f;`. These are consumed as raw `var(--sql-*)` color strings inside the CM `HighlightStyle` — NO `@theme inline` Tailwind aliases are required (CM styles are JS, not Tailwind utilities).
- Keep the suite green: `bunx tsc --noEmit` and `bun test` pass, including the updated `QueryTabView.test.tsx` and the new pure `sql-completions` test.

**Block If:**
- Faithfully wiring completion would require any Core / contract / RPC change (a new introspection RPC, a schema-completion endpoint, server-side ranking). It must NOT — the loaded `tables` prop already carries every name the completion needs. If a required name (schema/table/column) is genuinely unavailable client-side without a new round-trip, HALT `blocked` with condition `completion needs a Core/RPC change out of scope for a UI-only editor swap` rather than add an RPC.

**Never:**
- No SQL parsing/splitting/classifying/tokenizing to DECIDE execution or risk (AR-3). CodeMirror's grammar tokenizes only to COLOR and to COMPLETE; the text sent to `execute` is the raw doc, unchanged. The Core remains the sole risk classifier and gate.
- No change to `run-raw-query.ts`, the `execute` path, `RunOutcome`, `ConfirmRun`, shared contract types, or any `src/core/**` file. No new RPC method, no new `WORKSPACE_TAB_KINDS` member.
- No persisting query text, editor state, cursor, or history to disk / the `WorkspaceSnapshot` — the session-draft-only invariant is unchanged. CM history/undo is session-local and never serialized.
- No multi-statement enabling or client-side statement splitting — multi-statement is still rejected by the Core as `bad_request` (unchanged). Autocomplete/highlighting do not change what is or isn't a legal submission.
- No coral hex and no hardcoded Tailwind palette utilities on the editor surface — the CM theme resolves color ONLY through `globals.css` tokens (`--background`/`--foreground`/`--coral-soft`/`--card`/`--border`/`--sql-*`). Do NOT add a `[data-theme="light"]` override for `--sql-*` (dark-first, matching the Story 7.3 `--err*`/`--warn*` precedent); a light SQL palette is out of scope.
- Do not schema-refresh after a DDL run (pre-existing connect-time memoized-cache behavior, Stories 3.4/3.5/3.6) — completion reflects whatever `tables` currently holds (introspected + optimistically-created), which is the same source the ERD and PK lookup already use.

## Design Notes

- **Where the loaded schema lives (the completion's data source).** The introspected schema is already client-side and already threaded to the query Tab — no new RPC. `SchemaTree` fetches it via the `connect` RPC and fires `onSchemaLoaded(schema.tables)` → `App.setSchemaTables` (`App.tsx:293`, wired at `:583`). `App` folds it with optimistic `createdTables` into memoized `allTables` (`App.tsx:344–346`), passes it to `Workspace` as `allTables`, which passes it to `TabContent` as `tables={allTables}` (`Workspace.tsx:356`). `TabContent`'s `query` branch just needs to forward `tables={tables}` into `QueryTabView`. Each `SchemaTableInfo` carries `schema`, `name`, and `columns[].name` (+ `dataType`) — everything the completion needs. This is the same list the ERD and the PK-icon lookup already consume, so completion reflects created tables too.
- **Why a pure completion builder.** The repo has no jsdom/testing-library — only `bun:test` + `react-dom/server` for presentational structure (see `QueryTabView.test.tsx`'s own note). CodeMirror can't be mounted or driven in that harness. So the schema→completion mapping is extracted to a pure `sql-completions.ts` (exactly as `run-raw-query.ts` extracted the round-trip), where the name-derivation and prefix-filtering ARE unit-testable without a DOM; the CM wiring itself is verified live.
- **The textarea→CM swap breaks textarea-shaped tests (call-out).** Today `QueryTabView.test.tsx` asserts the draft text appears in `renderToStaticMarkup` output ("the textarea is seeded with the bound draft text"). CM builds its editable DOM in a client-side `useEffect`, which SSR does not run — so the doc text will NOT appear in server markup. That specific assertion must be reworked (assert the editor mount container + its accessible name/`data-testid` instead). The Run-button / disable-state / empty-state assertions survive because that chrome stays React-rendered outside CM. Update the test in the SAME change, keeping an equivalent accessible + testable Run + editor contract.
- **Keymap staleness + verbatim run.** CM extensions are fixed at construction, so the `Mod-Enter` keymap must call `runRef.current()` (a ref refreshed each render) to see the latest `busy`/`confirm`/gate, and `run()` must read the editor's CURRENT doc text (`view.state.doc.toString()`) — not the possibly-stale `draft` prop — before sending it verbatim to `runRawQuery`. The `updateListener` keeps `onDraftChange` in sync so the lifted `queryDrafts` map (and thus tab-switch persistence) still works, and the doc must be reconciled from an external `draft` change only when it actually differs (guard the listener feedback loop).
- **`Mod` == the existing gate.** CodeMirror's `Mod-Enter` binds Cmd on macOS and Ctrl elsewhere — exactly the current `e.metaKey || e.ctrlKey` behavior — so the cross-platform run shortcut (and the platform-aware `⌘↵`/`Ctrl ↵` chip label) stays correct.
- **Highlighting/completion are authoring aids, never the gate (AR-3).** CM's grammar tokenizes to color and to complete; it never decides what is sent or whether a statement is destructive. The exact doc bytes go to the Core, which remains the sole classifier and gate. This keeps the Story 3.6 / 3.1 invariant intact with zero Core change.
- **Dark-first `--sql-*`.** The syntax palette is net-new and dark-only, matching the Story 7.3 `--err*`/`--warn*` precedent (no light override). Because the CM `HighlightStyle` takes raw CSS color strings, the tokens are consumed as `var(--sql-kw)` directly — no Tailwind `@theme inline` aliases, unlike the shell's utility-class tokens.
- **Bundle sanity.** CodeMirror 6 is tree-shakeable pure ESM with no native modules, so `Bun.build` (browser target) folds it into the generated bundle and `--compile` still yields a self-contained binary. The only real risk is bundle-size growth (verify the build still succeeds and the binary still builds); there is no runtime-bundler or plugin dependency to add.

## Acceptance Criteria

- Given a query Tab, when the editor renders, then a CodeMirror 6 editor stands in place of the old textarea over a neutral mono surface matching `workspace.html`, and the ink-filled Run control + `⌘↵`/`Ctrl ↵` chip + pager chrome render unchanged.
- Given SQL typed in the editor, when it renders, then keywords (and strings/numbers/functions/punctuation) are syntax-highlighted via the `--sql-*`-mapped `HighlightStyle` — no hardcoded palette colors, all color through `globals.css` tokens.
- Given a loaded schema and a typed table prefix, when I press `Ctrl+Space`, then a neutral completion popup lists the matching table names (and schema/column names) drawn from the already-loaded `tables` — no new RPC — and typing a prefix also opens the popup as-you-type; selecting an option inserts that name at the caret.
- Given a runnable editor, when I press `⌘/Ctrl+Enter`, then `run()` still fires, reads the editor's current text, and sends it verbatim through the guarded `execute` RAW path exactly as before; the enable gate, the `firing` re-entrancy guard, the destructive `ConfirmRun` flow, and `run-raw-query.ts` are byte-for-byte unchanged.
- Given typed-but-unrun SQL, when I switch Tabs and back, then my draft is still in the editor (lifted `queryDrafts`), and on relaunch it is gone — query text still never touches disk or the workspace snapshot.
- Given the swap from textarea to CodeMirror, when the suite runs, then `QueryTabView.test.tsx` is updated to the new editor (the draft-in-markup assertion reworked to the CM mount container while keeping the same accessible/testable Run + input contract) and the new pure `sql-completions.test.ts` covers the completion builder.
- Given `bun run build` (and `bun run build:binary`), when the UI bundles, then the CodeMirror ESM graph bundles cleanly into `ui-bundle.generated.ts` and the `--compile` binary is still self-contained; `bunx tsc --noEmit` and `bun test` pass.
