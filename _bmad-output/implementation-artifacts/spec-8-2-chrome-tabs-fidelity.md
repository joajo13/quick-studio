## Intent

**Problem:** The Epic-7 neutral redesign (Story 7.1) shipped the workspace tab strip WITHOUT a live visual verification, and its review — chasing a spurious vertical scrollbar — deliberately *removed* the Chrome-style concave "feet" and the true active-tab/content-panel fusion rather than fixing their root cause. The current `TabBar`/`Workspace` are drifted from the prototypes (`design-artifacts/ai-chat-chatgpt.html` + `design-artifacts/workspace.html`, whose tab CSS is byte-identical and is THE contract). Concretely: (1) tabs are flat rounded-top boxes with NO carved feet; (2) the tablist wrapper carries `overflow-x-auto`, which — because CSS forces `overflow-y` to `auto` whenever the other axis is not `visible` — clips the feet/fusion AND spawns a vertical scrollbar whose up/down chevrons read as "unnecessary vertical scroll" and inflate the strip's height; (3) the active tab does NOT fuse into the content panel — the panel wrapper's `m-1.5` top gap leaves a visible dividing line/seam between the tab row and the content header; (4) inactive-tab hover keeps the tab (rounded-top) silhouette instead of the prototype's floating chip/pill; (5) the close `×` hover target is off-center; (6) the content panel is a fully-rounded, fully-detached floating card (`rounded-xl` + `m-1.5`) instead of a panel with rounded TOP corners only that sits square and flush to the window bottom. Nothing about tab *behavior* is wrong — only the skin and the overflow mechanics.

**Approach:** Presentation-only. Restore the prototype's Chrome-tab silhouette on `TabBar` and re-fuse it into `Workspace`'s content panel, matching `.topbar` / `.tabs` / `.tab` / `.tab.on` / `.tab .k` / `.tab .x` / `.tab-add` / `.content-panel` (identical in both prototypes) to the pixel. Carve the concave **feet** back via the prototype's `.tab.on::before` / `.tab.on::after` radial-gradient MASK layers (panel-colored 12×12px squares with a transparent circle punched at the inner-top corner, positioned at `left:-12px` / `right:-12px`, `bottom:0`) — pseudo-elements that do NOT participate in layout and therefore can only render if the tab strip's vertical axis is **never clipped**. Solve the overflow WITHOUT dropping the feet: keep the tab strip's vertical axis `visible` so feet + the 1px fusion overlap are never clipped, keep horizontal overflow scrolling for many-tab cases, and eliminate the spurious vertical scrollbar by NOT pairing `overflow-x:auto` with a clipped/short vertical box (the exact trap Story 7.1 hit). Reduce the strip to the prototype's `.topbar` padding (`5px 8px 0 6px`) and `.tab` height (36px rest / 37px active). Fuse the active tab: it shares the panel surface (`bg-card` = prototype `--bg`), sits directly on the panel top with a `-1px` overlap and NO intervening gap, so there is no seam. Make inactive hover a floating **pill** (`inset:4px`, `border-radius:10px`, all four corners), not a tab shape. Center the close `×` (`display:grid; place-items:center; 15×15px; border-radius:4px`). Reshape the content panel to rounded-TOP-only, square + flush bottom (deviation from the prototype's floating card, per the explicit user complaint — see Boundaries). All color comes from `globals.css` tokens (`bg-card`/`bg-background`/`text-foreground`/`text-muted-foreground`, neutral ink hover); no coral. The `design-artifacts/*.html` prototypes are the visual source of truth and SUPERSEDE any coral rule still worded in DESIGN.md / EXPERIENCE.md.

## Boundaries & Constraints

**Always:**
- Match the prototype tab contract to the pixel (identical in `design-artifacts/ai-chat-chatgpt.html` and `design-artifacts/workspace.html`):
  - `.topbar` — `display:flex; align-items:flex-end; flex-shrink:0; background:transparent; padding:5px 8px 0 6px; gap:2px;` (tabs bottom-aligned so the active one kisses the panel).
  - `.tabs` — `display:flex; align-items:flex-end; gap:3px; overflow:visible;` with the scrollbar hidden (`::-webkit-scrollbar{display:none}`); prototype comment: "overflow VISIBLE so the active tab's concave feet … are never clipped by a scroll box."
  - `.tab` — `display:flex; align-items:center; gap:8px; padding:0 14px; height:36px; border:none; border-radius:12px 12px 0 0; background:transparent; color:var(--text-faint); font-size:12px; letter-spacing:.01em; white-space:nowrap; position:relative; margin:0 8px; z-index:1; transition:color .12s;`.
  - `.tab.on` (active) — `color:var(--text); background:var(--bg); height:37px; margin-bottom:-1px; z-index:3;` (1px taller + `-1px` bottom margin → overlaps the panel top by 1px; shares `--bg` with the panel → fuses; NO border/hairline — the silhouette reads from contrast alone).
  - Concave **feet** — `.tab.on::before,.tab.on::after { content:""; position:absolute; pointer-events:none; bottom:0; width:12px; height:12px; background:var(--bg); opacity:1; z-index:2; }`, with `.tab.on::before{ left:-12px; mask:radial-gradient(circle at top left, transparent 11.5px, #000 12.1px); }` and `.tab.on::after{ right:-12px; mask:radial-gradient(circle at top right, transparent 11.5px, #000 12.1px); }`. The feet are panel-colored (`--bg`) squares with a transparent circle punched at the inner-top corner; the leftover crescent flares OUT and curves down into the panel, revealed against the deeper `--bg-deep` (#000) shown through the transparent topbar.
  - Inactive hover **pill** — `.tab:hover:not(.on)::before { inset:4px 4px 4px 4px; border-radius:10px; background:#ffffff0a; z-index:-1; opacity:1; }` (light: `#00000008`): a floating grey pill rounded on all four corners, symmetric inset, only opacity/background transition (zero geometry change), content stays centered — NOT a tab/trapezoid/rounded-top shape.
  - `.tab .k` (leading icon) — `width:13px; height:13px; color:currentColor; opacity:.85;`.
  - `.tab .x` (close) — `color:var(--text-faint); border-radius:4px; width:15px; height:15px; display:grid; place-items:center; margin-left:2px;` + `.tab .x:hover{ background:#ffffff1a; color:var(--text); }` (centered hover target).
  - `.tab-add` (new-tab `+`) — `background:transparent; color:var(--text-faint); width:34px; height:36px; align-self:flex-end; display:grid; place-items:center; padding:0; margin:0 2px; border-radius:10px; font-size:19px; line-height:1; font-weight:400;` + `.tab-add:hover{ color:var(--text); background:#ffffff0a; }` (same floating-pill hover idiom).
- Map the prototype's `--bg`/`--bg-deep` onto the codebase tokens: active tab + content panel = `--bg` (#0a0a0a) → `bg-card`; the topbar/window shown behind the tabs and revealed inside the feet notch = `--bg-deep` (#000) → `bg-background`. `--text` (#ececec) → `text-foreground`; `--text-faint` (#8f8f8f) → `text-muted-foreground`. The active tab and the panel MUST share `bg-card` and be vertically adjacent (`-1px` overlap, no gap) so they fuse into one silhouette.
- Solve the overflow WITHOUT dropping the feet: keep horizontal tab overflow scrollable (many-tab case) while the tab strip's vertical axis stays `visible` so the feet + the 1px fusion overlap are never clipped, and NO vertical scrollbar / up-down chevrons ever appear. If a horizontal scroller is used, its scrollbars must be hidden (`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`) and nothing may protrude past its block box on the vertical axis.
- Consume `globals.css` tokens / Tailwind utilities only (`bg-card`, `bg-background`, `text-foreground`, `text-muted-foreground`, and a neutral ink hover wash such as `bg-accent`/`bg-coral-soft` matching the prototype's faint `#ffffff0a` / light `#00000008`). No coral hex, no coral color value.
- Content panel: rounded **TOP** corners only (`12px 12px 0 0`, matching the tab's top radius), square + flush at the **bottom** (no bottom gap, no rounded bottom corners), and NO gap at the top so the active tab fuses onto it. This is a deliberate deviation from the prototype's `.content-panel { border-radius:12px; margin:0 6px 6px 6px; }` floating card, mandated by the user complaint that the panel must sit flush to the window bottom.

**Block If:**
- The Chrome-tab feet / active-fuse look cannot be expressed without restructuring `TabBar`'s DOM in a way that breaks the `role="tab"` / `aria-selected` / `tabIndex` / `onKeyDown` / close-button-`aria-label` contract — HALT `blocked`, condition `tab chrome cannot be styled without breaking the tab a11y contract`. (It can: the prototype achieves feet purely with `::before`/`::after` on the tab element, requiring no new DOM.)

**Never:**
- No logic, state, RPC, prop, routing, or event-handler changes — presentation only. Do not touch `workspace-state.ts`, the reducer, tab open/close/activate wiring, `PanelGroup`/`Panel`/`PanelResizeHandle`, `ExposureBanner`, the status bar's connection indicator + Stop, or the Settings/Create mutually-exclusive toggles.

Keep `TabBar` returning `null` on zero tabs.
- Keep the new-tab `+` control (its `title`/`aria-label="New tab"` and `onOpen` handler unchanged) and every `data-testid` on the shell (`settings-toggle`, `create-table-toggle`, `exposure-banner`, `health`).
- No coral: no coral/orange hex, no revival of the `--coral` color value, no coral-tinted chrome. The accent is ink.
- Do not re-introduce the Story-7.1 failure mode: no `overflow-x:auto` (or any non-`visible` overflow) on a box that must let the feet / fusion overflow — that forces `overflow-y:auto` and clips them + spawns the vertical scrollbar.
