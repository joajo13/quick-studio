## Intent

**Problem:** New Table opens as an OVERLAY, not a tab. Clicking the rail's `create-table-toggle` flips a React-memory-only `createOpen` flag in `Workspace.tsx` (`useState(false)`, line 294) whose `toggleCreate` (295-297) superimposes `<CreateTablePanel>` over the whole main Panel and HIDES the tab strip + new-tab `+` (the strip is gated on `!createOpen`, line 343; the body is a two-way branch `createOpen ? <CreateTablePanel/> : <TabContent/>`, 368-397). While Create is open you cannot see or reach your open tabs — to get back to your work you must first CLOSE Create. This is the SAME overlay pathology Settings had before Story 8.6, and the same fix applies: Settings already moved overlay → tab (`openOrFocusSettings`, a `settings` singleton kind, `TabContent` routing, a repointed rail toggle). `design-artifacts/workspace.html` shows the rail's create-table `+` opening a normal working surface alongside the tab strip, not a modal that eats it. Create-table is a VIEW you author in, not a modal.

**Approach:** Make New Table a NORMAL TAB in the tab strip, and a SINGLETON — you author one new table at a time, so a second click on the rail toggle FOCUSES the already-open create-table tab instead of opening a duplicate or re-overlaying. This is the EXACT 8.6 move, applied to create-table: a new `openOrFocusCreateTable(state)` reducer helper (focus the existing create-table tab, else open exactly one, title `"New Table"`, no numeric suffix), `CreateTablePanel` mounted as that tab's body through `TabContent`, and the rail `create-table-toggle` (testid preserved) repointed to that open-or-focus action. Delete the create-table overlay branch, the `createOpen` state, and `toggleCreate` entirely. `CreateTablePanel`'s behavior is PRESERVED VERBATIM — schema pickers, typed column rows, the `buildCreateTableOp` DDL compose, the `execute {shape:"structured", op}` create RPC, the double-submit `inFlight` ref guard, the never-expected `confirmation_required` defensive branch, `data-testid="create-table-panel"`, every `role="alert"` (ErrorLine, line 39), and `aria-label="Close create table"` — this is a RELOCATION, not a rewrite. Its `onClose` (which the panel already calls on a successful create, `CreateTablePanel.tsx:207-209`) now CLOSES the create-table tab via the normal `closeTab` path, so the "auto-close on success" behavior is preserved by construction.

**Persistence — NON-persist, and enforced at the type layer (the one deliberate divergence from 8.6).** Unlike Settings (which 8.6 added to the shared `WORKSPACE_TAB_KINDS` contract enum and PERSISTS across reload), create-table is a TRANSIENT authoring surface: its entire value is the live draft (table name + column rows), which is React-memory-only and NEVER serialized. A restored create-table tab would be a blank, purposeless form; worse, the surface is one-shot (it self-closes on `status:"ok"`). So create-table must NOT persist. Rather than add it to the contract enum and then filter it back out on save, make the UI's `TabKind` a SUPERSET: `type TabKind = WorkspaceTabKind | "create-table"` (`workspace-state.ts:38`). The persisted `WorkspaceSnapshotTab.kind` stays `WorkspaceTabKind` (contract.ts UNTOUCHED — the five document kinds + `settings`), so `toWorkspaceSnapshot`'s tab `.map` (`workspace-state.ts:350`) that assigns into the annotated `WorkspaceSnapshot` becomes a COMPILE ERROR until a `.filter((t) => t.kind !== "create-table")` is added — tsc PROVES create-table never reaches disk. And on the load side, Core's `isTabKind` derives from `WORKSPACE_TAB_KINDS` (which excludes create-table), so a hand-edited snapshot carrying `kind:"create-table"` is REJECTED by Core validation — `restoreWorkspace` can never see one, and needs no create-table defense. Non-persist is guaranteed at BOTH the save type-boundary and the load validation boundary, with ZERO Core edits and no `WORKSPACE_SNAPSHOT_VERSION` bump.

## Boundaries & Constraints

**Always:**
- Model the create-table tab through the EXISTING pure tab reducer (`workspace-state.ts`): it opens (open-or-focus), activates, and closes via the same `activateTab`/`closeTab` machinery as every other tab — no parallel, out-of-band `createOpen` flag survives anywhere.
- Widen the UI `TabKind` to the SUPERSET `WorkspaceTabKind | "create-table"` (`workspace-state.ts:38`), leaving `src/shared/contract.ts` UNTOUCHED. This is the deliberate divergence from 8.6 (which widened the contract enum): create-table is UI-only and non-persisted, so it must NOT enter the persisted `WORKSPACE_TAB_KINDS` / `WorkspaceSnapshotTab.kind`. Keep `WORKSPACE_SNAPSHOT_VERSION = 1`.
- Enforce the singleton at the SOLE open seam: a new pure `openOrFocusCreateTable(state)` helper FOCUSES the existing create-table tab if one is open (delegates to `activateTab`), else appends exactly one create-table tab (title `"New Table"`, no numeric suffix) and makes it active. The rail toggle and the App action route only through this helper. Mirror `openOrFocusSettings` (`workspace-state.ts:175-181`) exactly.
- Route `tab.kind === "create-table"` in `TabContent` to `<CreateTablePanel>`, mounting it as the tab body in the exact same `overflow-auto` slot the overlay used. Thread `schemas` and `onTableCreated` down into `TabContent` (Workspace already receives both as props — `Workspace.tsx:281,283 / 620-621`) and pass `onClose={() => onCloseTab?.(tab.id)}` so both the panel's "close" button AND its post-create auto-close call `closeTab`. Add `key={tab.id}` to match every sibling branch.
- Preserve `CreateTablePanel` VERBATIM (relocation only): `data-testid="create-table-panel"` (223), `aria-label="Create table"` (223) / `"Close create table"` (232) / `"Remove column"` (147), every `role="alert"` (ErrorLine, 39), the schema `<select>` + column-row type `<select>`, `validateCreateTableDraft` / `buildCreateTableOp` / `isCreateTableError` / `synthesizeSchemaTable` compose path, the `execute {shape:"structured", op}` create RPC (NO `confirmed` — createTable auto-commits, 198-199), the `inFlight` double-submit ref guard (176, 189, 195, 200), the defensive `confirmation_required` inline-error branch (212-214), and the `onCreated`→`onClose` success sequence (206-210). Its props `{ schemas, onCreated, onClose }` (156-166) are unchanged; only the CALLER's `onClose` target changes (close the tab, not hide an overlay).
- Repoint the rail `create-table-toggle` (`Workspace.tsx:138-152`): keep `data-testid="create-table-toggle"`, `aria-label="Create table"`, `title`, and the `+` glyph; change `onClick` to the new `onOpenCreateTable` (open-or-focus) and `aria-pressed` to `activeTab?.kind === "create-table"` (truthful "you're viewing create-table"). It stays a bottom-pinned rail toggle (like the Settings toggle beside it), NOT a per-kind launcher button.
- Keep the rail's per-kind launcher loop over `LAUNCHER_KINDS` (the five document kinds) so create-table never gains a launcher button; extend `LAUNCHER_KINDS`'s filter to exclude BOTH `settings` AND `create-table` (`workspace-state.ts:92`).
- Add a `create-table` entry to every exhaustive `Record<TabKind, …>` map so tsc stays green: `KIND_LABEL` (`workspace-state.ts:75`, `"New Table"`), `LAUNCH_LABEL` + `KIND_ICON` (`Workspace.tsx:30,42` — filler, create-table is not a launcher kind), `TAB_ICON` (`TabBar.tsx:18` — a real leading icon, reuse the rail's `+` plus glyph), `KIND_BLURB` (`TabContent.tsx:57` — filler, the create-table body never renders the placeholder).
- Route `openTab` defensively: add `if (kind === "create-table") return openOrFocusCreateTable(state)` at the top of `openTab` (`workspace-state.ts:103`, beside the existing `settings` guard at line 107) so no caller can mint a numeric-suffixed `"New Table 2"` duplicate that bypasses the singleton.
- Guard the new-tab `+` fallback (`Workspace.tsx:355`): `+` duplicates the active tab's kind, so extend the existing `!== "settings"` guard to ALSO exclude `"create-table"` (`onOpen(activeTab && activeTab.kind !== "settings" && activeTab.kind !== "create-table" ? activeTab.kind : LAUNCHER_KINDS[0]!)`) — `+` opens a document kind, never a second create-table tab.
- Add a NON-persist filter to `toWorkspaceSnapshot` (`workspace-state.ts:350`): `state.tabs.filter((t) => t.kind !== "create-table").map(…)`. tsc will FORCE this (the `WorkspaceTabKind`-typed snapshot won't accept the widened union) — treat the compile error as the required signal, not an accident.
- Preserve every tab a11y hook in `TabBar` (`role="tablist"`/`role="tab"`/`aria-selected`/`tabIndex`/Enter-Space activation, close-button `aria-label`) and keep `ExposureBanner`, the `PanelGroup`/`Panel` resizable layout, and the bottom status bar (connection indicator + Stop) — all untouched.
- Update AND extend `workspace-state.test.ts`: add coverage for `openOrFocusCreateTable` (open-when-none, focus-when-present, no-op-when-already-active), the `openTab("create-table")` singleton routing, and a `toWorkspaceSnapshot` NON-persist assertion (a create-table tab is DROPPED from the snapshot; `activeTabId` behavior confirmed) — without breaking any existing assertion.

**Block If:**
- If `TabKind` cannot widen to `WorkspaceTabKind | "create-table"` without forcing an edit to `src/shared/contract.ts` or the persisted `WorkspaceSnapshotTab.kind` (the whole point is that create-table stays UI-only and OUT of the contract) — HALT `blocked`, condition `create-table kind cannot stay out of the persisted contract enum`.
- If the Chrome tab strip cannot render a `create-table` tab body without restructuring `TabContent`'s kind routing in a way that breaks the `role="tab"`/`aria-selected`/close-button contract — HALT `blocked`, condition `create-table tab body cannot mount without breaking the tab a11y contract`.
- If any `CreateTablePanel` testid / `role="alert"` / RPC / compose / guard line cannot survive the move verbatim (i.e. the relocation would require touching the panel's internals) — HALT `blocked`, condition `create-table panel behavior cannot be preserved as a pure relocation`.

**Never:**
- No overlay / superimposed create-table surface — create-table is a tab, full stop. Do NOT keep the `createOpen` flag, `toggleCreate`, the `createOpen ? <CreateTablePanel/> : <TabContent/>` branch, or the `!createOpen` strip gate.
- No second create-table tab, ever — NO code path (rail toggle, App action, the new-tab `+`, or `openTab`) may yield two create-table tabs.
- No persistence of a create-table tab — it must NEVER appear in a `WorkspaceSnapshot` (enforced by the `toWorkspaceSnapshot` filter + the `WorkspaceTabKind` type boundary) and Core must never accept one on load (it isn't in `WORKSPACE_TAB_KINDS`). Do NOT add `"create-table"` to `contract.ts` and do NOT bump `WORKSPACE_SNAPSHOT_VERSION`.
- No change to `CreateTablePanel`'s RPC method/params, the createTable auto-commit (no `confirmed`), the `inFlight` guard, `validateCreateTableDraft`/`buildCreateTableOp`/`synthesizeSchemaTable`, the optimistic `onCreated(synthesizeSchemaTable(draft))` tree append, its props, or its testids/`role="alert"` — the ONLY wiring change is that `onClose` now closes the create-table tab.
- No change to Settings' now-tab behavior (8.6) — Settings stays a persisted singleton tab; this story only removes the create-table overlay.
- No removal of `ExposureBanner`, the `PanelGroup` layout, or the status bar; no coral / off-brand chrome regression — the create-table tab wears the same neutral Chrome tab treatment as every other tab (Epic 7).

## Acceptance Criteria

- **Given** no create-table tab is open, **when** the rail create-table control (`data-testid="create-table-toggle"`) is clicked, **then** a single `"New Table"` tab appears in the tab strip (leading `+` icon + close `×`), becomes active, and its body renders `CreateTablePanel` (`data-testid="create-table-panel"`) in the normal tab-body slot — no overlay superimposes over the workspace and the tab strip stays visible.
- **Given** a create-table tab is already open, **when** the create-table control is clicked again, **then** the existing create-table tab is focused/activated, NO second tab is created (singleton), and the in-progress draft is preserved.
- **Given** a create-table tab, **when** it is closed via the tab `×` or the panel "close" (`aria-label="Close create table"`), **then** it is removed through the normal `closeTab` path and the nearest sibling activates.
- **Given** a create-table tab with a filled, valid draft, **when** submit returns `status:"ok"`, **then** the table is optimistically appended to the schema tree (`onCreated`) AND the create-table tab auto-closes (`onClose` → `closeTab`) — identical to the overlay era's success flow.
- **Given** the new-tab `+` while the create-table tab is active, **then** `+` opens a document tab and never a second create-table tab.
- **Given** a create-table tab is open, **when** the workspace is saved and the app reloaded, **then** the create-table tab is NOT persisted and does NOT reopen (transient surface); a snapshot never carries `kind:"create-table"` and Core rejects any hand-edited one.
- **Given** `CreateTablePanel`, **when** inspected, **then** its schema/column pickers, `buildCreateTableOp` DDL compose, `execute {shape:"structured"}` create RPC (no `confirmed`), `inFlight` double-submit guard, `confirmation_required` defensive branch, `role="alert"` lines, and `data-testid="create-table-panel"` are identical to before — only its mount site (tab body vs overlay) and `onClose` target changed.
- **Given** the suite, **when** run, **then** `bunx tsc --noEmit` is clean, `bun test` is green with `workspace-state.test.ts` extended (new `openOrFocusCreateTable` / `openTab` routing / non-persist tests) and no existing assertion broken, and `bun run build` succeeds.
