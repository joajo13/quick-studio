Architecture Spine · Solution Design

quick-studio

A lightweight, local-first database manager — one command to run, a fast web UI on 127.0.0.1, a multi-provider AI chat that turns questions into queries, and local report generation. This is the architecture that keeps every feature honest to one promise: lightweight is the identity, fast is the promise.

The paradigm

Three rings of trust

Data flows outward only; capability never flows inward.

The whole product is one privilege-separated local web app. Three concentric rings of decreasing trust, and no feature may build a path that lets a less-trusted ring reach a more-trusted ring's resources. This is the security model — there are no user accounts; the ring boundary is the boundary that matters.

1

Trusted Core · Bun process

Sole holder of DB connections, decrypted credentials, and Provider keys. The only SQL executor and the only Provider caller. Home of the destructive-statement guard and port-exposure watcher.

2

Semi-trusted UI · browser origin

React / shadcn. Orchestrates the workspace but holds no credential and runs no SQL — it asks the Core over localhost with a session token.

3

Untrusted Sandbox · cross-origin iframe

Where the LLM's generated MDX JavaScript runs. Pure render, fed one-way. No network, filesystem, backend, credential, or SQL access — it can only draw.

data → outward · requests → inward

The decisions

16 architecture invariants

Each fixes a call a future builder couldn't read off compliant code — the durable half of the contract. security marks a boundary invariant; gate-hardened marks one tightened or added by the adversarial review that closed a real hole.

AD-1

Three-ring trust model is the root invariant

RuleEvery runtime unit belongs to exactly one ring. Data passes outward; capability and requests cross only to the ring immediately inward, via that boundary's authenticated channel. No unit widens its own ring's powers. Bindsall
AD-2

The Core is the sole holder of secrets, sole SQL executor, sole Provider caller

RuleConnections, decrypted credentials, and Provider keys exist only in the Core; all SQL runs there; every outbound Provider call is made there. Rings 2 & 3 issue typed requests and receive results — never holding a credential or running SQL. BindsFR-4, 7–11, 14, 15
AD-3 gate-hardened

The Sandbox is a cross-origin iframe, pure-render, fed one-way

RuleMDX JS runs in a separate-origin iframe — allow-scripts without allow-same-origin, CSP default-src 'none'. The channel is one-way for data: Ring 2 pushes frozen data in; the sandbox emits only render/interaction signals out. It cannot request data or trigger a query. In-process isolation (SES/QuickJS/ShadowRealm) is never the boundary — only the cross-origin process boundary is. BindsFR-17, R1
AD-4 gate-hardened

One Core executor gates every mutation; confirmation policy is set by request shape, not by ring

RuleEvery mutation runs through one Core executor — the sole classifier of risk (a UI dialog is UX, never the gate). It accepts two request shapes: (a) Structured operations — typed, parameterized UI-builder requests (single-row grid DML by primary key, and the create-table builder); the Core composes the SQL, so the path can express only a single-row INSERT/UPDATE/DELETE or a CREATE TABLE — never DROP/TRUNCATE/ALTER, raw, multi-row, or multi-statement; INSERT, single-row UPDATE, and CREATE TABLE auto-commit, row DELETE always confirms. (b) Raw SQL text — query Tab / AI, classified as opaque text; UPDATE, DELETE, DROP, TRUNCATE, ALTER are default-deny, always confirmed, and multi-statement input is rejected or split so nothing rides behind a safe SELECT; DROP/TRUNCATE/ALTER can arrive only on this path. The invariant holds — all mutation flows through the one executor, always parameterized; only the confirmation policy differs by shape. BindsFR-8, 9, 11, 15, R4
AD-5

Credential Store: encrypted at rest, key in OS keychain, passphrase fallback, never plaintext

RuleAES-256-GCM file; 32-byte key in the OS keychain (Windows Credential Manager / Linux Secret Service); passphrase-derived key when no keychain. Plaintext is never written, even as fallback. Ephemeral keys are session-only, in memory. BindsFR-4, 5, 6, 14, R2
AD-6

Localhost by default; active exposure watcher

RuleBinds 127.0.0.1 unless explicitly overridden. A watcher raises a prominent Port-Exposure Warning on any non-loopback binding, explaining the risk and how to revert. BindsFR-21, 22, R3
AD-7 gate-hardened

The Core owns the Provider boundary via a typed payload; schema-only default

RuleThe one outbound channel is the user's Provider, called by the Core. The request is a typed, Core-inspectable structure with schema and any row-sample as distinct fields — never opaque UI free text — so the Core enforces schema-only by default; rows go only via explicit, per-query, visible opt-in. Runs on the user's own keys: no account, no hosted cost (R6). BindsFR-15, 17, R5, R6
AD-8

Ephemeral mode writes nothing to disk

RuleNo Credential Store, no ERD layout, no Report, no panel state. All session state is in-memory and gone at exit; no daemon outlives the process. BindsFR-2, 3
AD-9 gate-hardened

A Live Report carries no credential and re-queries only through a running, authorizing quick-studio

RuleA Snapshot embeds frozen data and renders offline. A Live Report holds no credential and no DB runtime; it re-queries only by targeting a running Core on 127.0.0.1, which explicitly authorizes it (AD-12) and supplies the connection. Re-targeting re-runs queries without rebuilding the layout. BindsFR-19, 20
AD-10

Charting is split by ring

RuleIn-app charts (Ring 2) use Recharts / shadcn; sandbox charts (Ring 3, no React host) use Observable Plot (framework-agnostic). TradingView lightweight-charts is dropped — financial-OHLC focus, wrong fit for generic DB data. BindsFR-17, 18
AD-11

Streaming is SSE; reasoning is a distinct channel from the answer

RuleCore→UI streaming (tokens, reasoning, large result pages) uses SSE over localhost. Model reasoning is rendered as a channel visually distinct from the final answer. BindsFR-16, NFR-6
AD-12 security new · closes DNS-rebind

The Core authenticates every caller — session token + anti-rebinding

RuleThe Core rejects every RPC without the current session's capability token and validates Origin/Host to block DNS-rebinding — loopback alone is not an auth boundary. The UI gets the token at boot. A Live Report is authorized only as an explicit second caller (AD-9). BindsFR-2, 21, 22, R3
AD-13 new

One canonical frozen-data shape across every boundary

RuleA single shared, versioned frozen-data schema (in shared/) is the only shape pushed to the Sandbox and embedded in a Snapshot. Wire conventions (ISO-8601 UTC dates, typed values) bind UI↔Sandbox exactly as Core RPC — never live Date objects one path, ISO strings the other. BindsFR-17, 18, 20
AD-14 new

Engine-dialect isolation lives inside the Core

RuleAll Postgres/MySQL-specific SQL, introspection, and pagination live only in the Core behind one uniform driver interface; Rings 2 & 3 see an engine-neutral shape. The Core owns pagination/virtualization and never ships a whole live result set. BindsFR-7, 9–12, NFR-5
AD-15 new

Persistent state lives under one OS-convention app directory

RuleStore, ERD layouts, Reports, panel/session state, and logs live under a single app-data dir (%APPDATA%\quick-studio / $XDG_DATA_HOME/quick-studio). No scattering — the footprint promise holds. Ephemeral writes nothing. BindsFR-4, 6, 13, 24
AD-16 new

Dual distribution: standalone binary and runtime package

RuleTwo install paths, one run: a standalone bun build --compile binary per platform (the headline "one command, no runtime" path) and an npm/bun global package for devs who already have a runtime. BindsFR-1, 2

The stack

Full TypeScript, verified current

One language end-to-end — the JS-heavy AI / MDX / chart core wants it, the builder is fluent in it, and an accepted ~200 MB footprint defuses the pull toward a Go/Rust backend. Load-bearing libraries were verified against their registries at authoring; framework majors are cold-start seed to confirm at scaffold.
