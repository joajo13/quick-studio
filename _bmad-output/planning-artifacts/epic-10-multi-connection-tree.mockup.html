Multi-connection schema tree

Today quick-studio is single-connection: the boot manager is captured once and never swapped, so in persistent mode you can save connections but not browse them. This is the target: a DBeaver-style tree — one collapsible root per connection, introspected lazily on expand, and inside each connection a collapsible schema level (a Postgres DB has many: public, auth, reporting…). Click the roots, schemas and tables below — it behaves like the real thing. The right column maps each behavior to its story.

schema
Hard invariant (AR-12) — do not break it. Only the opaque connectionId crosses the loopback RPC. The URL, user, and password stay in Ring 1 (Core) and are resolved there via connectionTargets.resolve(id). The boot manager stays the default target (id = null), so ephemeral mode is byte-for-byte unchanged. Out of scope: cross-connection joins — each tab runs against exactly one connection.
